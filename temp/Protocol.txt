통신 프로토콜 명세

1. 공통 규칙

- 문자 인코딩: UTF-8
- 메시지 끝: 줄바꿈
- 메시지 필드 구분: |
- Task 필드 구분: ,
- P2P 다중 Task 구분: ;

2. Task 형식

id,key,value,attempts,retry,enqueuedAt

- id: 4자리 작업 번호
- key: 고유 4자리 16진수 Key
- value: 1~100 정수
- attempts: 처리 시도 횟수
- retry: 재시도 작업 여부(true/false)
- enqueuedAt: Master 가상 시각(ms)

예시

0001,a3f7,83,0,false,1000

3. Master - Worker 메시지

Worker -> Master

HELLO|workerId|p2pPort
Worker 등록 요청

STATUS|queueSize
현재 Ready Queue 크기 보고

RESULT|taskId|attempt|SUCCESS/FAIL|duration|wait|queueSize|PROCESS/QUEUE_FULL
작업 처리 결과 보고. 처리 실패와 Queue 초과 거부를 구분한다.

P2P|SENT/RECEIVED|peerId|transferId|count|taskRefs
P2P 작업 전송 또는 수신 결과 보고. taskRefs 형식은 taskId:attempt 목록이다.

NET|messageType|sourceWorkerId|targetWorkerId
Worker 간 단방향 메시지 1건을 Master System Clock에 반영한다.

TERMINATE_ACK
종료 완료 응답

Master -> Worker

WELCOME|masterClockMillis
Worker 등록 완료 및 Master 가상 시각 전달

TASK|id,key,value,attempts,retry,enqueuedAt
작업 배정

START|masterClockMillis
초기 Queue 배정 완료 후 Worker 처리 Thread 시작 신호

RESULT_ACK|taskId|attempt|SUCCESS/FAIL|masterClockMillis
처리 결과 확인 및 확정 가상 시각 전달

P2P_ACK|SENT/RECEIVED|peerId|transferId|count|taskRefs|masterClockMillis
P2P 결과 확인 및 확정 가상 시각 전달

TERMINATE|masterClockMillis|faultReassignments|p2pEvents
정상 종료 요청과 최종 가상 시각, 전체 장애 재할당 수, 전체 P2P 이전 이벤트 수 전달

FINAL_CLOCK|masterClockMillis
모든 TERMINATE_ACK의 통신 지연까지 반영된 공통 최종 가상 시각 전달.
시각 동기화용이므로 별도 지연은 부과하지 않는다.

REJECT|reason
Worker 등록 거부

4. Worker - Worker P2P 메시지

QUEUE_QUERY|requestId|sourceWorkerId
대상 Worker의 현재 Ready Queue 크기 조회

QUEUE_STATUS|requestId|workerId|queueSize
Queue 조회 응답. queueSize 범위는 0~10이다.

TRANSFER|transferId|sourceWorkerId|task1;task2;...
최소 Queue Worker 작업 이전 요청. transferId는 재전송 중복 수신을 방지한다.

ACK|transferId
작업 수신 완료

REJECT|reason
Queue 여유 공간 부족 또는 이전 거부

5. 메시지 예시

추가 P2P 상태 확인:
TRANSFER_STATUS|transferId|sourceWorkerId
TRANSFER_STATE|transferId|ACCEPTED 또는 NOT_FOUND 또는 REJECTED
ACCEPTED: 이미 수락한 전송. 작업이 처리된 뒤에도 수락 기록을 유지한다.
NOT_FOUND: 수락 기록이 없으며 해당 ID를 취소 확정한다. 이후 늦게 도착한 TRANSFER도 거절한다.
REJECTED: 이미 거절 또는 취소 확정한 ID이다.
조회 실패/미지원 응답은 송신 측 UNKNOWN으로 처리한다. 복원하지 않고 예약 유지·재조회한다.
transferId는 sourceWorkerId-양의순번 형식이며 실행 중 재사용하지 않는다.
상태는 메모리에만 보관한다. 서로 다른 버전의 Worker를 섞어 실행하지 않는다.

HELLO|1|6001
TASK|0001,a3f7,83,0,false,1000
RESULT|0001|0|SUCCESS|2.14|0.50|3|PROCESS
P2P|SENT|2|1-17|3|0088:0,0089:0,0090:0
QUEUE_QUERY|Q1-17|1
QUEUE_STATUS|Q1-17|2|3
TRANSFER|1-17|1|0088,b7c2,21,0,false,8000;0089,c2b5,55,0,false,8000
