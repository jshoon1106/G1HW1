로그 형식
  [가상 시각] 노드 | 이벤트 | 상태 | 내용

상태
  INFO    일반 진행 정보
  SUCCESS 연결, 처리, 이전, 종료 성공
  FAIL    처리 실패, Queue 초과, 연결 실패, 전체 처리 제한시간 초과
  WARN    Queue 70% 초과, 잘못된 프로토콜 메시지, 중복 결과, ACK 제한시간 초과

이벤트
  INIT       Master 시작, KV 작업 5,000개 생성
  CONNECT    Worker 연결, 연결 해제
  RECV       Master 작업 수신
  DISTRIB    Master 작업 배정, 전체 처리 완료
  RESULT     Worker 성공·실패 결과 수신
  PROC       Worker 작업 처리 결과
  QUEUE      Queue 용량 경고, 초과 거부
  LB         Worker 간 Queue 조회, P2P 작업 이전·수신·ACK 확인, 이전 KV 번호 기록
  NET        노드 간 단방향 메시지별 1초 통신 지연 반영
  PROTO      알 수 없거나 형식·범위가 잘못된 네트워크 메시지
  KV         최종 Key-Value 저장소 전체 출력
  STAT       Master·Worker 최종 통계
  TERMINATE  정상 종료 신호, 종료 완료

추가 규칙
  QUEUE WARN은 실제 대기 작업 수의 변경 전 또는 후가 7을 초과할 때 작업마다 기록한다(7→8 및 8→7 포함).
  P2P 묶음 송수신, 실패 복원, 종료/연결 오류 정리에도 각 작업의 전후 크기·작업 ID·사유를 기록한다.
  P2P 복원 예약 슬롯은 용량 제한에 포함하지만 WARN의 실제 Queue 크기에는 포함하지 않는다.
  처리 또는 종료 ACK 제한시간 초과 시 Master 최종 TERMINATE는 FAIL이며 SUCCESS로 덮어 기록하지 않는다.
  Worker는 종료 신호와 최종 시각을 확인한 경우만 TERMINATE SUCCESS를 기록한다.
  최종 시각 수신 제한시간 초과·대기 중단은 TERMINATE FAIL로 기록하며 실패 시에도 통계는 남긴다.
  RESULT 로그는 20% 처리 실패와 Queue 초과 거부를 구분한다.
  동일 taskId와 attempt의 중복 RESULT는 최초 1건만 반영한다.
  P2P 전송은 transferId로 중복 수신을 방지한다.
  Master 통계에는 처리 실패 수와 Queue 초과 거부 수를 별도로 기록한다.
  장애 재할당 수는 20% 처리 실패와 Worker 연결 해제로 인한 재할당만 집계한다.
  Worker별 작업 처리량은 해당 Worker가 성공적으로 처리한 KV 쌍의 수로 기록한다.
  Worker별 장애 재할당 횟수는 해당 Worker의 20% 처리 실패 횟수로 기록한다.
  P2P 이벤트 수와 P2P로 이동한 작업 수는 별도 집계한다.
  노드 간 애플리케이션 메시지의 단방향 전송마다 Master System Clock에 1초를 누적한다.
  요청과 응답은 별도 전송으로 계산하며, 시각 동기화와 종료 후 로그 파일 전송은 수행시간에서 제외한다.
  Worker별 P2P 부하 분산 이벤트 횟수는 해당 Worker의 전송 이벤트와 수신 이벤트 합계로 기록한다.
  각 노드의 최종 STAT에는 작업 처리량, 성공·실패 횟수, 평균 대기시간, P2P 부하 분산 이벤트 횟수,
  장애 재할당 횟수, 전체 수행시간을 기록한다.
  Queue 초과 거부, 재시도 작업 수신, P2P 작업 송수신 세부 건수는 개별 이벤트에는 기록하지만
  Worker 최종 STAT에는 중복 출력하지 않는다.
